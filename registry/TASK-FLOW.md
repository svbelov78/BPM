# Типовая задача — локальный флоу

Источник: [Products BPM / Типовая задача](https://www.figma.com/design/tOFCfQUjfFvAB0Pgqxb9xQ/Products-BPM?node-id=73-6302), макеты из «Типовая задача (1).pdf». Библиотека Nordic не изменялась.

## Использование

В «Моём кабинете» или разделе «Задачи» нажмите «Создать задачу» → «Типовая». Заполните название и выберите ответственных. Процесс, инсайт, описание, срок и вариант результата можно указать дополнительно. Дата вводится как ДД.ММ.ГГГГ или выбирается в общем календаре; он поддерживает одиночный выбор в этой форме и прежний диапазон в фильтрах.

После нажатия «Создать» Drawer закрывается без автоматического открытия деталки. Открывается реестр задач, вкладка «Исходящие», первая страница с сортировкой по дате создания от новых к старым. Поиск и фильтры очищаются, чтобы новая задача была видна первой. Появляется toast «Задача создана» с зелёной галочкой. Карточный/табличный вид сохраняется. Это правило действует и при создании из кабинета.

Новая задача также появляется в ленте кабинета. Если среди ответственных есть текущий демонстрационный пользователь Иванов Иван Васильевич, она появляется также во входящих. Клик по карточке или строке типовой задачи открывает деталку.

Нижняя панель формы всегда остаётся одной строкой высотой 50 px: «Отменить» — сброс — «Создать»/«Сохранить». Сброс не сдвигает остальные кнопки; на узкой ширине показана его иконка с полным названием в подсказке и доступном имени. Список ответственных открывается над селектом и прокручивается внутри доступной высоты.

Чтобы редактировать свою задачу, нажмите на название, описание, срок или список ответственных в деталке. Открывается состояние редактирования из макета. «Сохранить» включается после изменения; «Сбросить» восстанавливает исходное состояние; «Отменить» возвращает просмотр без сохранения. У инициатора без назначения себе видны «Отозвать» и белая кнопка «Закрыть». У входящей задачи — «Отклонить» и «Завершить». В отозванной, отклонённой или завершённой задаче снизу остаётся белая кнопка «Закрыть».

Подпись относительного срока нейтральная: «Срок: 17 дней» для прошедшей или будущей даты, «Срок — сегодня» для текущей даты. Индикаторы результата завершённой задачи («Закрыта в срок» / «Превышен срок») сохраняются.

Отклонение требует обоснования. Завершение допускает пустой финальный комментарий. Эти действия записывают статус и комментарий локально; после завершения показывается индикатор «Закрыта в срок» либо «Превышен срок». Повторная обработка завершённых/отклонённых/отозванных задач не предлагается. Инициатор может открыть редактирование завершённой задачи — это отдельный макет состояния из PDF. Отозванные и отклонённые задачи доступны только для просмотра.

Ссылка «Типы задач» сохраняет незавершённую форму при возвращении к выбору типа. «Отменить» в создании очищает её. Закрытие крестиком/Escape сохраняет черновик только в памяти до перезагрузки. Вложенная панель сначала закрывается своим Escape; следующий Escape закрывает Drawer.

## Данные и ограничения

- Это прототип, не рабочий сервис: задания и уведомления другим людям не отправляются.
- Изменения хранятся в `localStorage`, ключ `bpm-task-store:v1`; изначальные данные не перезаписываются в файлах. При недоступном хранилище работает текущая сессия, без гарантии сохранения после перезагрузки.
- HTML по `file://` и локальный сервер имеют разные хранилища. Перенос HTML/ZIP на другой компьютер не переносит созданные в браузере задачи.
- Ответственные, инсайты, процессы и варианты берутся из уже включённых в прототип данных. Варианты показываются только там, где они есть в этих данных; новые варианты не выдумываются.
- Неопределённые в макетах проверки формы сведены к обязательным названию/ответственным и корректности введённой даты. Прошедшие даты допустимы для демонстрации просрочки.
- Остальные семь форм создания не реализованы: на них остаётся сообщение о необходимости макета.

## Проверка

`BPM_TASKS_URL=http://127.0.0.1:4187/ node test-task-flow.cjs` — браузерные проверки нового флоу (Playwright + Chrome). `BPM_TASK_FLOW_FILE=../Sber-BPM-Registry-Standalone.html node test-task-flow.cjs` проверяет автономную копию под другим именем. `node build-standalone.cjs` пересобирает автономный файл из тех же исходников.
