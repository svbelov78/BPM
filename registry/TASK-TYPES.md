# Дополнительные типы задач — локальный прототип

Добавлено 29.09.2026. Источник: восемь PDF и соответствующие макеты [Products BPM / Задачи](https://www.figma.com/design/tOFCfQUjfFvAB0Pgqxb9xQ/Products-BPM?node-id=1-172). Библиотека Nordic в Figma не изменялась при реализации HTML.

## Сценарии

| Тип | Реализованные состояния |
| --- | --- |
| Согласование расширенного доступа к процессу | Создание, просмотр, редактирование, согласование, отклонение, доработка и повторная отправка |
| Управление ролями | Добавление/удаление роли, выбор варианта и сотрудника, подтверждение ознакомления, принятие/отклонение, итоговая карточка решения |
| Чек-лист самопроверки актуальности Бизнес-описания | Выбор БО, восемь вопросов, рекомендация, решение и комментарий; при необходимости актуализации — одна связанная задача |
| Создание варианта предоставления результата процесса | Создание нескольких вариантов, просмотр существующих, редактирование/удаление предложенных карточек, отдельные сценарии изменения и удаления существующего варианта, сравнение до/после, решения по вариантам |
| Неприменимость метрик | Добавление нескольких метрик, период или бессрочность, обоснование, индивидуальные решения, согласование, отклонение и доработка |
| Массовая неприменимость метрик | Каналы и метрики, все процессы или настраиваемые группы, период, обоснование, итог и однократное восстановление применимости с комментарием |
| Актуализация Бизнес-описания | Создание, ответ «обновлено / не требует актуализации», регистрационный номер для обновлённого БО, отправка на проверку, согласование и доработка |
| Задача к инсайту | Выбор инсайта со связанным процессом, создание, просмотр, редактирование, завершение, отклонение и отзыв |

Типовая задача сохранена: всего в выборе девять типов. Доступные действия зависят от состояния задачи и участия текущего демонстрационного пользователя.

## Общие правила

- Входы: реестр задач, «Мой кабинет», блок задач в деталке процесса. Вложенный Drawer открывается поверх исходной деталки; закрытие возвращает фокус и не сбрасывает её прокрутку.
- После создания форма закрывается, новая задача видна первой в реестре и появляется toast с зелёной галочкой. Деталка автоматически не открывается.
- У каждой формы свой черновик в памяти. Переход к выбору типа и крестик сохраняют его до перезагрузки; «Отменить» очищает. «Сбросить» возвращает исходные значения.
- Проверяются обязательные поля, выбранные сущности, реальные календарные даты и порядок дат периода. Пустые обязательные коллекции и согласование без выбранных позиций не принимаются.
- В конечных состояниях форма доступна для просмотра. Повторное согласование или восстановление уже обработанной задачи не выполняется. При изменении статуса в другой вкладке устаревшее действие отклоняется.
- Использованы существующие поля, селекты, календарь, теги, аватары и точные SVG из Figma. Формы адаптированы до 320 px; меню ответственных открывается вверх, вложенные панели имеют собственную прокрутку и обработку Escape.

## Данные и границы прототипа

Задачи и комментарии хранятся только в `localStorage` (`bpm-task-store:v1`). Формат расширен полями `flowType` и `flowData`, ранее созданные типовые задачи совместимы. При недоступном хранилище изменения живут только в текущей сессии. Перенос HTML на другой компьютер не переносит данные браузера.

Процессы, люди и инсайты выбираются из данных прототипа. Недостающие каталоги метрик, вариантов предоставления результата, услуг, сегментов и БО — демонстрационные. Для процесса используются его реальные включённые в прототип варианты, если они есть; иначе показывается демонстрационный набор. Ссылки на учебный портал и внешние системы не подключены.

Согласование отражается в задаче: настоящие права, роли, каталог процессов и серверная применимость метрик не меняются. Задачи и уведомления другим людям не отправляются. В чек-листе связанная задача актуализации создаётся локально один раз после соответствующего решения. Автоматическое повторение по расписанию, серверные сроки и рассылки не реализованы.

## Исходники и проверка

- `task-types-a.js`, `task-types-b.js`, `task-types-checklist.js` — поля, проверки и переходы каждого типа.
- `special-task-flow.js` — общий контроллер форм, Drawer, сохранения и вложенных панелей.
- `task-collections.js` — карточки метрик и вариантов; `special-task-flow.css` — оформление и адаптив.
- `task-store.js` — совместимое локальное хранение; `task-flow.js` — прежняя типовая задача.

Из папки `registry`:

```sh
node build-standalone.cjs
node test-special-task-flow.cjs
BPM_SPECIAL_TASK_FILE=../Sber-BPM-Registry-Standalone.html node test-special-task-flow.cjs
BPM_TASK_FLOW_FILE=../Sber-BPM-Registry-Standalone.html node test-task-flow.cjs
node test-standalone.cjs
```

Браузерным тестам нужны Playwright и Chrome; сайту зависимости не нужны. Проверки используют отдельный профиль, а автономную версию копируют под другим именем в пустую временную папку и открывают без сети. Хранилище рабочего браузера пользователя не затрагивается.
